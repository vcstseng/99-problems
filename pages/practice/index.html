從問題目錄，走向有證據、可審查的顧問方案

我們正在建立一個 Consulting Agent Group：用可重用的顧問能力處理不同企業問題。先透過少數案例跑通問題理解、分析、方案與管理審查，再逐題擴展。目標是支援 99 個問題，不是宣稱它們已經全部解決。

我們的 Consulting Agent Framework

用同一套工作框架，依問題組合所需能力。領域知識與顧問方法可以隨案件完善，不必每題重新建立整個流程。

Agents · Skills · Tools

Agents 承接與協調職責；Skills 提供領域知識與顧問方法；Tools 執行受限資料讀取、計算與獨立查核。需要 AI 才用 AI，確定性方法足夠時就用確定性方法。

Security · Governance

限定來源與必要存取、追溯版本、設置審查與停止關卡。人保留責任與決策權；Agent 的建議不是實施授權。

釐清問題 → 調查分析 → 證據查核 → 提出方案 → 管理審查 → 顧問交接。 人機協作貫穿全程，交付可信的顧問方案，現階段不做自主部署。

99 題已有候選能力對應，實作與驗證仍需逐案累積。F03 已有完整條件式方案；CS07、GOV08 目前為有界本機流程展示。正式企業安全與真實商業成效仍待驗證。

01

從少數案例開始，建立共用方法

問題地圖回答「有哪些問題」；方法論說明「如何整理問題」；這裡記錄「我們實際用什麼方式嘗試解題，以及驗證到哪裡」。

每題先釐清決策、所需資料與成功條件，再選擇合適的方法。不把所有問題硬套 AI：能用確定性計算、規則或流程改善處理的部分，就先用這些方法。需要模型判斷時，仍須保留證據、限制與驗證。

02

Agents、Skills、Tools 如何分工？

Agents：安排與承接工作

問題規劃、領域分析、證據檢查與管理審查是不同職責。邏輯角色不等於每個都要部署獨立 AI 模型；依案件需要組合。

Skills 與 Tools：方法與執行

Skills 提供成本差異、假設驗證、方案比較等方法；Tools 執行指定資料查詢、計算與查核。角色名稱或技能文件本身不代表已具備實作能力。

目前完成 99 題能力盤點與對應，部分能力已實作。展示流程主要使用固定規則與合成資料；不是 99 個自主 Agent，也尚未驗證對全部問題的自動解題能力。

03

從問題走到完整顧問交付

  1. 問題釐清：確認目標、範圍、資料與成功標準。
  2. 調查計畫：選擇方法、允許工具與責任角色，列出需要的證據。
  3. 分析與查核：執行計算或查詢；用獨立領域規則檢查數字、來源、版本與授權。
  4. 方案比較：分開事實、根因假設與估算，說明選項、取捨及推薦理由。
  5. 管理審查：補證據、退回修改、重驗、接受有界交付，或拒絕／停止。
  6. 顧問交接：提供執行路線、責任分工、資源、風險、驗收與未結決策。

本團隊的定位是顧問交付。需要 AI 或系統時，可以提出需求與導入建議；目前不承接客戶軟體開發、部署或現場變更。

04

人如何管理 Agent 的工作？

重點不只是產生答案，而是能看懂、追問、退回和停止。每版分析都保留證據與檢查結果；管理指示綁定版號，修改後重新驗證，不把舊版接受套到新版。

Agent 準備

分析、建議、假設、缺口與交付文件。不能自行宣告驗證通過，也不能把建議當作實施授權。

人類決定

確認目標與口徑、判斷專業適用性、核定資源與風險，決定是否推進。預算、實施與正式核准仍屬真實責任人。

目前案例的管理指示與接受紀錄由同一助手模擬，並非使用者本人核准或獨立專家審查。真人協作與操作可用性仍待驗證。

05

安全與治理是流程的一部分

  • 限定範圍：使用 host 指定來源與工具，不讓分析文字自行授權新存取。
  • 證據可追溯：記錄來源雜湊、計算、檢查與限制；來源改變需重新審查。
  • 版本與恢復：本機案件引擎保存分析、管理指示與拒絕紀錄，可重啟繼續，攔截舊版本決策與衝突寫入。
  • 有界接受：接受分析不等於核預算、執行變更或消除風險；有缺口時補證據或停止。
  • 不誇大控制：本機測試與模擬身份不是正式登入、企業 IAM、多租戶隔離或正式安全認證。

這個網站目前呈現靜態成果，不提供即時案件控制，也不連接本機 Agent 後端。
