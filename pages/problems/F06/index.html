F06 財務

市場突然發生以前沒遇過的事，該做哪些壓力測試？

具有匯率、利率或商品價格曝險的企業，在遇到新的地緣政治、政策或市場事件時，既有量化模型雖然能計算已定義的壓力測試，卻很難快速把新的外部事件轉成和企業曝險有關、可實際測試的風險情境。

01

問題是什麼？

具有匯率、利率或商品價格曝險的企業，在遇到新的地緣政治、政策或市場事件時，既有量化模型雖然能計算已定義的壓力測試，卻很難快速把新的外部事件轉成和企業曝險有關、可實際測試的風險情境。

02

需要知道什麼？

新事件出現時，風險團隊先要知道它可能影響哪些匯率、利率、商品價格或企業部位，並找得到可參考的歷史事件與既有壓力測試。重點是把外部新聞轉成和公司曝險有關的可測試假設。

主要資料

FX/利率/商品曝險、部位、Risk Factors、歷史市場事件與反應、外部新聞/政策、既有Stress Scenarios

既有系統

TMS/Risk System、ERP、Market Data Feed、外部資訊源

03

AI 改變了什麼？

成熟的量化模型已能計算 VaR、敏感度與壓力測試結果；AI/LLM 的額外價值，是把新的外部事件連結到企業曝險、歷史類比與相關風險因子，協助提出可測試的情境架構，而不是自行決定衝擊幅度或取代核心風險模型。

04

怎麼解？

先把新的政策、地緣或市場事件連到相關 Risk Factors 與企業曝險，再找歷史類比，提出幾組可測試的壓力情境。真正的損失計算仍交給既有量化模型，AI 不自行決定衝擊幅度。

Solution Core

Event-to-Risk-Factor Mapping + Historical Analogue Retrieval + Existing Quant Stress Testing

05

AI 做什麼？

解析新的市場、政策與地緣事件，辨識可能受影響的匯率、利率、商品等風險因子與企業曝險，搜尋歷史類比並提出壓力測試情境，再交由既有量化模型計算財務影響。

06

人決定什麼？

風險與資金管理人員設定或核准衝擊幅度，判斷歷史類比與情境是否合理，使用既有風險模型驗證影響，並決定是否採取避險或流動性行動。

07

最後改善什麼？

縮短從新事件發生到形成可測試風險情境的時間，在不取代成熟量化模型的前提下，更快理解企業曝險與可能損失。

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
