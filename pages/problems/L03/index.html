L03 法務／合規

制度都寫好了，但實際營運有沒有照做？哪個內控正在失效？

企業雖然已建立政策與內控，但執行證據散落在交易、系統紀錄、核准 Email、工單與附件中，很難持續確認內控是否真的有執行，也不容易找出哪些例外缺少證據、需要人工調查。

01

問題是什麼？

企業雖然已建立政策與內控，但執行證據散落在交易、系統紀錄、核准 Email、工單與附件中，很難持續確認內控是否真的有執行，也不容易找出哪些例外缺少證據、需要人工調查。

02

需要知道什麼？

內控制度寫在文件裡不代表現場真的有做。要把 Control Requirements、交易、系統 Log、Approval、附件、Exception 與過去 Audit Findings 放在一起，確認每個控制是否真的有證據。

主要資料

Control Requirements、交易、System Logs、Approval Email/Tickets、附件、Exception、Audit Findings與Remediation

既有系統

GRC、ERP、Workflow/Identity、DMS、Audit System

03

AI 改變了什麼？

職務分離、核准額度、重複付款等結構化內控，可以用規則或 SQL 持續檢查；AI/LLM 的額外價值，在於把內控要求和 Email、工單、附件等非結構化證據比對，判斷證據是否存在或不足，並協助大量例外分流。

04

怎麼解？

先用確定性規則檢查結構化交易與系統紀錄，再從 Email、工單和附件找支持控制執行的證據。反覆例外、證據缺失或互相矛盾的案件優先交給合規或稽核調查。

Solution Core

Deterministic Control Testing + Unstructured Evidence Matching + Exception Triage + Remediation Tracking

05

AI 做什麼？

先用既有規則與內控邏輯檢查結構化交易與系統紀錄，再從 Email、工單與附件中找出支持內控執行的證據，標示缺少或互相矛盾的證據與反覆例外，排出需要合規或稽核進一步調查的案件。

06

人決定什麼？

合規與內部稽核確認證據是否足以證明內控有執行，判斷例外是否構成缺失、分析根本原因並要求改善；AI 不能自行宣告內控有效或完成稽核判斷。

07

最後改善什麼？

把持續監控從結構化規則延伸到原本難以大量檢查的非結構化證據，更早發現證據缺口與內控失效，降低人工交叉核對負擔。

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
