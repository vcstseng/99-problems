S08 銷售

如果業績沒達標，是哪個環節出了問題？

當銷售績效偏離目標時，管理者需要先判斷差距來自Pipeline量、轉換率、平均售價、銷售週期或產品/客戶組合，再進一步找出造成變化的原因

01

問題是什麼？

當銷售績效偏離目標時，管理者需要先判斷差距來自Pipeline量、轉換率、平均售價、銷售週期或產品/客戶組合，再進一步找出造成變化的原因

02

需要知道什麼？

業績沒達標時，第一步不是直接找人負責，而是先把差距拆開：Pipeline 夠不夠、轉換率有沒有掉、平均售價是否下降、銷售週期是否拉長，還是產品、客群或通路組合改變。

主要資料

銷售KPI、目標、Pipeline階段與轉換率、平均售價、Sales Cycle、產品/客戶/通路/活動維度與實際成交

既有系統

CRM、ERP、DWH/BI、Marketing Analytics

03

AI 改變了什麼？

銷售差距本身可先用明確的Funnel與Driver Decomposition拆解；AI的額外價值在於跨大量結構化與非結構化資料辨識異常、排序可能原因並產生可驗證假設，但Driver關聯不能直接視為因果。

04

怎麼解？

先用可解釋的銷售漏斗與 Driver 拆解業績差距，再從客戶、商機、通路與活動資料找異常和可能原因。AI 可以幫忙排序值得追查的假設，但真正的根因仍要靠業務與管理者驗證。

Solution Core

Sales Funnel Decomposition + Anomaly Detection + Hypothesis Generation

05

AI 做什麼？

先將業績差距拆成Pipeline Volume、Conversion、ASP、銷售週期與Mix等可觀察Drivers，再從客戶、Deal、通路與活動資料尋找異常與可能原因，提出可驗證假設

06

人決定什麼？

驗證AI提出的原因假設、區分相關性與真正原因，並決定改善行動

07

最後改善什麼？

縮短從發現銷售落差、定位問題環節到形成可驗證原因假設與採取行動的時間

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
