SEC06 安全

一個 Agent 被攻破，會不會沿著信任關係一路影響其他 Agent？

多Agent系統中，一個遭操縱或Compromised Agent的自然語言輸出可能被其他Agents當成Instruction、Evidence或Delegated Request，再透過共享Memory、Tools與權限鏈向外擴散

01

問題是什麼？

多Agent系統中，一個遭操縱或Compromised Agent的自然語言輸出可能被其他Agents當成Instruction、Evidence或Delegated Request，再透過共享Memory、Tools與權限鏈向外擴散

02

需要知道什麼？

多 Agent 系統裡，一個 Agent 的輸出常會被另一個 Agent 當成輸入。要先看清楚 Agent 身份、訊息來源、Delegation Chain、共享記憶、工具權限與彼此信任關係，才能知道攻擊會怎麼傳播。

主要資料

Agent Identities、Messages、Delegation Graph、Message Provenance、Shared Memory、Tool Permissions與Trust Relationships

既有系統

Agent Platform、Message Bus、IAM、MCP

03

AI 改變了什麼？

傳統Service-to-Service Interface通常具有較明確的Schema與Trust Boundary；多Agent系統可能把自然語言輸出直接作為另一個Agent的Context或Instruction，使Compromise沿信任鏈傳播。此類攻擊與偵測仍屬Early，主要控制應是Isolation與Explicit Trust Boundaries而非依賴語意偵測。

04

怎麼解？

把每個 Agent 的身份、記憶與工具權限隔離，跨 Agent 訊息都保留來源與委派鏈，不讓其他 Agent 自動把外部輸出當成可信指令。發現異常傳播或權限跳躍時，要能快速停止 Delegation 並隔離來源。

Solution Core

Agent Isolation + Explicit Trust Boundaries + Message Provenance + Least Privilege + Propagation Containment

05

AI 做什麼？

隔離Agent的Identity、Memory與Tool Permissions，標記跨Agent訊息的來源與Delegation Chain，避免其他Agents自動把外部Agent輸出視為可信Instruction；偵測異常權限跳躍或傳播時支援快速隔離與停止Delegation

06

人決定什麼？

定義Agent-to-Agent Trust、可委派Authority、共享資料範圍與Emergency Shutdown Authority，決定何時隔離Agent或整條Delegation Chain

07

最後改善什麼？

限制單一Agent Compromise沿共享Context、Tools與Delegation關係擴散，降低Cascading Compromise的Blast Radius

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
