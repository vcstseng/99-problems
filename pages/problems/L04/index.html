L04 法務／合規

交易量這麼大，哪些真的可疑、值得人去查，而不是系統誤報？

金融與支付業每天產生大量交易，固定 AML 規則容易出現大量誤報，也可能漏掉跨帳戶、裝置與交易對手形成的複雜關聯，使有限的調查人力無法集中在真正值得深入查核的案件。

01

問題是什麼？

金融與支付業每天產生大量交易，固定 AML 規則容易出現大量誤報，也可能漏掉跨帳戶、裝置與交易對手形成的複雜關聯，使有限的調查人力無法集中在真正值得深入查核的案件。

02

需要知道什麼？

AML 或交易監控每天可能產生大量 Alert，真正重要的是哪些具有高風險證據。要把交易、KYC、帳戶與裝置關聯、交易對手、歷史 Alert 結果與 Watchlist 一起看，避免只靠單一規則。

主要資料

交易、KYC、Counterparty、帳戶/裝置關聯、歷史Alerts、Case Outcomes、Watchlists與必要外部風險資訊

既有系統

Core Banking/Payments、AML/KYC、Data Lake

03

AI 改變了什麼？

AML 規則仍應作為監管要求與已知態樣的基線；圖譜與行為模型可以補捉規則難以發現的關聯與異常，協助警示優先排序。但歷史案件標記會受到既有規則與過去查核方式影響，模型分數不能直接當成可疑交易的事實。

04

怎麼解？

保留既有 AML 規則，再加入交易異常與實體關聯分析，把多個風險訊號合成可解釋的調查優先順序。系統負責縮小範圍與整理證據，最後是否可疑仍由調查人員判斷。

Solution Core

AML Rules + Transaction Anomaly Detection + Entity/Network Analysis + Alert Prioritization

05

AI 做什麼？

保留既有 AML 規則，同時分析交易行為、帳戶、裝置、交易對手與實體關聯，找出異常模式與關聯風險，整合規則與模型訊號後排序警示，並整理調查所需的交易與關聯證據。

06

人決定什麼？

AML／合規人員驗證規則與模型提供的證據、調查實際情境，並決定案件是否升級與法定申報；低風險分數不能直接拿來自動放行。

07

最後改善什麼？

降低無效誤報造成的調查負擔，同時提高對複雜關聯與新興可疑模式的可見性，讓有限的 AML 人力優先處理高風險案件。

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
