VER07 可靠性與驗證

昨天還能用，換了模型、Prompt 或 Tool 後，今天怎麼悄悄壞掉了？

Model、Prompt、Tool、Retrieval Pipeline、Policy或Evaluator的變更都可能改變AI Behavior；由於輸出具有非確定性，傳統單次Unit Test可能無法發現Quality、Safety或Decision Behavior的Regression

01

問題是什麼？

Model、Prompt、Tool、Retrieval Pipeline、Policy或Evaluator的變更都可能改變AI Behavior；由於輸出具有非確定性，傳統單次Unit Test可能無法發現Quality、Safety或Decision Behavior的Regression

02

需要知道什麼？

AI 系統一換 Model、Prompt、Tool、Retrieval 或 Policy，行為就可能改變。要保留版本、Gold Cases、Edge Cases、Adversarial Cases、Production Sample 與過去 Evaluation，才能判斷新版本到底變好還是悄悄退步。

主要資料

Version History、Gold/Representative Cases、Adversarial Cases、Production Samples、Model/Prompt/Tool/Policy Configs與Historical Evaluation Results

既有系統

Git、CI/CD、Evaluation Platform、Agent Registry、Observability Platform

03

AI 改變了什麼？

AI Behavioral Regression不能只用傳統Exact-Match Unit Tests判斷；需要代表性Gold Cases、Edge/Adversarial Cases、Repeated Runs與Statistical Thresholds比較不同版本。Temperature=0也不保證完全Deterministic，供應商模型更新則需要Version Pinning與Canary Evaluation降低Silent Change風險。

04

怎麼解？

每次重要變更前後都重跑代表性與高風險測試，用多次執行與統計門檻比較品質、安全、成本和行為差異。重大版本先做 Canary Evaluation，再逐步放大部署範圍。

Solution Core

AI Regression Testing + Representative Evaluation Sets + Statistical Comparison + Canary Evaluation

05

AI 做什麼？

在Model、Prompt、Tool、Retrieval或Policy變更前後重跑Gold Cases、Edge Cases、Adversarial Cases與代表性Production Samples，以多次執行與統計門檻比較Quality、Safety、Cost與Behavior Drift；重大版本先以Canary方式驗證再擴大部署

06

人決定什麼？

建立有代表性的Evaluation Set，決定Release Criteria、Statistical Tolerance與哪些Regression不可接受，並對重大Behavior Change做Release或Rollback決策

07

最後改善什麼？

更早發現AI Stack變更造成的Silent Degradation，避免單次測試或表面平均分數掩蓋重要Behavioral Regression
