SEC05 安全

AI 如果記錯一次，會不會把錯誤或惡意內容一直當成真的？

持久化Memory或共享Context可能把來自不可信來源、錯誤推論或惡意內容寫成未來Agent會重複使用的Context，使一次污染持續影響之後的判斷與行為

01

問題是什麼？

持久化Memory或共享Context可能把來自不可信來源、錯誤推論或惡意內容寫成未來Agent會重複使用的Context，使一次污染持續影響之後的判斷與行為

02

需要知道什麼？

長期 Memory 一旦寫錯，後續很多判斷都可能把錯誤當成事實。要知道每筆記憶是誰寫的、來自哪個來源、可信度、時間與版本，也要能辨識它和其他資訊是否互相矛盾。

主要資料

Memory Records、Conversation History、Source Provenance、Trust Level、User Identity、Timestamps、Write Events、RAG Stores與Knowledge Sources

既有系統

Vector DB、Knowledge Base、Agent Memory、DMS

03

AI 改變了什麼？

AI Memory把非結構化內容轉成未來Decision Context，而語意上可靠辨識所有Poisoned Memory目前並不可行；主要控制應是決定哪些來源有資格寫入長期Memory，並保留Provenance、Trust Level、Version與Expiration，而不是期待另一個模型事後判斷真假。

04

怎麼解？

對 Memory Write 設置信任門檻，不可信內容或 Tool Output 預設不能直接進長期記憶。重要記憶要有來源、版本、到期與隔離機制，發現異常時能修正或撤回，而不是讓錯誤一直被重用。

Solution Core

Memory Provenance + Trust-Based Write Gates + Versioning + Expiration + Quarantine

05

AI 做什麼？

對Memory Write記錄來源、Identity、Trust Level與時間，不可信內容與Tool Output預設不得直接寫入長期Memory；對重要Memory提供Versioning、Expiration、Quarantine與人工修正機制，矛盾或異常偵測作為輔助訊號

06

人決定什麼？

定義哪些Sources與Workflows有資格建立或修改Memory、保留期限與人工修正/刪除規則，對高影響長期記憶建立Review與Recovery機制

07

最後改善什麼？

限制錯誤或惡意資訊從單次互動變成持久Context，降低Memory Poisoning長期改變Agent行為與後續決策的風險

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
