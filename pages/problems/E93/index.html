E93 系統性後果

十個 AI 都給出一樣的答案，真的代表有十份獨立判斷嗎？

企業同時使用多個 AI Agent、部門模型或分析工具時，看似獨立的建議，可能其實共用同一個基礎模型、資料來源、Prompt、上游分析或假設。結果「大家都同意」可能只是同一個觀點被複製很多次，而不是多份獨立證據得出相同結論。

01

問題是什麼？

企業同時使用多個 AI Agent、部門模型或分析工具時，看似獨立的建議，可能其實共用同一個基礎模型、資料來源、Prompt、上游分析或假設。結果「大家都同意」可能只是同一個觀點被複製很多次，而不是多份獨立證據得出相同結論。

02

需要知道什麼？

多個 AI 給出同樣答案時，要先知道它們是否其實用了同一個 Model、Prompt、RAG 來源、上游分析或相同假設。沒有這些 Lineage，看起來像十份獨立意見，可能只是同一條證據鏈被重複十次。

主要資料

Agent Outputs、Model IDs、Prompts、Retrieved Sources、Upstream Analysis、Assumptions、Decision Records

既有系統

Agent Platform、LLM Gateway、RAG、Data Catalog、Decision Logs

03

AI 改變了什麼？

傳統決策流程通常假設不同分析來源具有一定獨立性；在多 Agent 環境裡，這個假設很容易失效。AI 可以協助追蹤可觀測的來源、依賴關係與語意相似度，但不能把看不到的模型內部推理假裝成可稽核證據。

04

怎麼解？

為每個建議保留模型、Prompt／Policy、檢索證據、假設與上游輸出的來源，建立 Decision Dependency Map。只有確認不同答案真的來自不同證據與推理路徑，才能把一致性當成有意義的訊號。

Solution Core

Decision Provenance + Dependency Mapping + Diversity Controls

05

AI 做什麼？

追蹤每個建議使用的模型、Prompt／Policy 版本、檢索證據、假設與上游輸出，建立可觀測的依賴關係，辨識多個答案是否其實來自同一條證據鏈或共同來源。

06

人決定什麼？

決定哪些重大決策真正需要獨立判斷，刻意安排不同資料、模型、方法或人工挑戰；不能把 Agent 票數直接當成信心。

07

最後改善什麼？

看見表面共識背後的共同依賴，降低共同失效風險；無法保證觀點真正獨立，但至少不會把重複訊號誤認成多份證據。

08

實驗：相同答案，不等於獨立證據

限定的來源相依查核通過；自主 Agent 團隊能力仍未證明。十份合成報告雖然同意同一結論，卻都透過轉載與摘要追到同一原始來源。十份報告，不代表十份獨立支持的判斷。

10 份報告 → 共用轉載與摘要 → 1 個已揭露原始來源

查核的是可見來源關係，未知的相依仍保留；即使根來源不同，也不能直接推論統計獨立或內容為真。

哪裡失敗？後來改了什麼？

未改動的原始工具清單無法執行來源相依查核，首次準備失敗已保留。補上受限來源追溯工具及另一套程式驗證後，用同一版流程與標準重新測試，沒有降低門檻。

09

驗證整個流程，不只看答案

先凍結問題與標準 → 確認準備 → 分析 → 挑錯 → 重驗 → 對精確版本決策 → 帶限制交付。缺證據就停止推進；中途改標準會讓原 run 失效，不把失敗改成成功。

檢查與證據

八種合成情境涵蓋共用與不同根來源、上游報告、矛盾證據、缺漏、循環引用、來源指令與無關來源。新增 25 項檢查、完整 249 項回歸通過；這是程式與流程檢查，不是獨立模型或商業成效驗證。

另測退回重驗與重試上限、過期決策、停止後恢復、來源改動攔截。本次主要接受 run 只有一版分析，未發生實際退回；退回路徑由另外的控制測試驗證。

實驗紀錄與限制 JSON · 合成來源圖 · 凍結驗收標準

分析由確定性工具執行，角色審查由同一助手完成；不是盲測，也不是多個隔離 AI 互相挑錯。隱藏相依、獨立推理、真實證據與商業成效仍未證明。
