GOV01 治理與控制

公司到底有多少 AI 在未經核准下運作？它們各自能碰什麼、做什麼？

企業缺乏完整且持續更新的AI、Agent、Copilot與Shadow AI Inventory，尤其是員工自行採用的SaaS、內嵌Copilot與動態建立的Agents，使Owner、用途、Capabilities、資料存取與風險無法被一致治理

01

問題是什麼？

企業缺乏完整且持續更新的AI、Agent、Copilot與Shadow AI Inventory，尤其是員工自行採用的SaaS、內嵌Copilot與動態建立的Agents，使Owner、用途、Capabilities、資料存取與風險無法被一致治理

02

需要知道什麼？

要治理 AI，第一步是先知道公司到底用了哪些 AI Service、Agent、Model 和 Tool，包括 SaaS、OAuth App、Cloud Resource、網路流量與採購紀錄。沒有完整清單，就無法談權限、資料使用或風險分級。

主要資料

AI API Traffic、SaaS Inventory、OAuth Apps、Browser/Network Logs、Cloud Resources、Expense/Procurement Data、Vendor Documentation與Runtime Agent Registry

既有系統

CASB、IAM、CMDB、Cloud、Procurement

03

AI 改變了什麼？

AI資產發現主要可由Network、OAuth、SaaS與Cloud Inventory等確定性方法完成；新的困難在於AI Capability會嵌入既有SaaS或動態產生，且Vendor文件與條款中的Data Use、Training、Retention與Action Capability需要語意理解才能進一步分類風險。

04

怎麼解？

先用 Network、OAuth、Cloud 與採購資料發現 AI 使用，再要求 Runtime Agent 主動登錄，形成一致的 AI Asset Inventory。之後整理每個資產的能力、資料存取、Retention／Training Practices 與風險等級。

Solution Core

Deterministic AI Discovery + Runtime Agent Registration + Capability/Risk Classification + AI Asset Inventory

05

AI 做什麼？

從Network、OAuth、SaaS、Cloud與Procurement資料發現AI Services，再結合Runtime Registration建立Agents、Models與Tools清單；LLM輔助解析Vendor Documentation與Terms，整理Capabilities、Data Access、Retention/Training Practices與可能風險

06

人決定什麼？

確認Owner、Business Purpose、Risk Tier與允許的Capabilities，決定是否核准或限制使用；同時設定員工監控資料的合法用途、Access與Retention Policy

07

最後改善什麼？

讓企業持續知道AI在哪裡、誰在使用、能碰什麼資料與具有哪些Capabilities，降低Shadow AI與未受治理Agent造成的風險
