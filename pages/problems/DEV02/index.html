DEV02 AI 原生開發

Codebase 這麼龐大，Coding Agent 真的知道改一個地方會影響哪裡嗎？

AI Coding Agent即使找到語意上相關的Code，也可能漏掉Runtime Configuration、Types、Schemas、Cross-Repo Dependencies、Reflection或其他不容易從文字相似度發現的Structural Dependencies，造成局部修改產生非預期影響

01

問題是什麼？

AI Coding Agent即使找到語意上相關的Code，也可能漏掉Runtime Configuration、Types、Schemas、Cross-Repo Dependencies、Reflection或其他不容易從文字相似度發現的Structural Dependencies，造成局部修改產生非預期影響

02

需要知道什麼？

大型 Codebase 裡，一個小改動可能跨 Repository、API、Schema、Runtime Config 和相依模組。要同時看 Code、Call Graph、Type／Dependency Graph、Test、Architecture Doc 與歷史變更，不能只把幾個相關檔案丟給 Agent。

主要資料

Code、Call Graph、Type/Dependency Graph、Runtime Config、APIs、Schemas、Tests、Cross-Repo Dependencies、Architecture Docs與Historical Changes

既有系統

Git、IDE、Code Search、Static Analysis、Architecture Repository

03

AI 改變了什麼？

AI適合從大型Repository理解Task Context與搜尋語意相關資訊，但Semantic Retrieval與Context Window不能證明Dependency完整性；Call Graph、Type Checking、Dependency Analysis、Schema/Contract Validation與Test-Impact Analysis等Deterministic Developer Tools應提供Structural Facts。

04

怎麼解？

先用語意搜尋找出和任務相關的 Code 與歷史脈絡，再用 Call Graph、Type／Dependency、Schema／Contract 和 Test Impact 做確定性檢查。最後組成 Task-specific Context，讓 Agent 知道能改哪裡、可能影響哪裡。

Solution Core

Semantic Repository Intelligence + Deterministic Dependency Analysis + Task-Specific Context

05

AI 做什麼？

先以語意搜尋找出與Task相關的Code、Architecture Decisions與Historical Context，再呼叫Call Graph、Type/Dependency Analysis、Schema/Contract與Test-Impact工具確認Structural Dependencies，組成Task-Specific Context供Agent修改與驗證

06

人決定什麼？

維護Architecture Constraints與關鍵System Boundaries，處理工具無法發現的Undocumented、Runtime或Business Dependencies，並核准重大Design Changes

07

最後改善什麼？

降低Agent因Context Retrieval遺漏或只理解局部Code而造成的Unexpected System Impact，使修改前的Impact Analysis更完整
