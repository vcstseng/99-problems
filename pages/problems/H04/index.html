H04 人資

這個人真正缺什麼能力？下一步該補哪個技能？

員工的技能證據分散在履歷、專案、工作成果、績效與Assessment中，而且「曾經做過或被提及」不等於真正具備熟練度，使企業難以可靠判斷能力缺口與發展優先順序

01

問題是什麼？

員工的技能證據分散在履歷、專案、工作成果、績效與Assessment中，而且「曾經做過或被提及」不等於真正具備熟練度，使企業難以可靠判斷能力缺口與發展優先順序

02

需要知道什麼？

要判斷一個人真正缺什麼能力，不能只看履歷或技能標籤。要把專案成果、績效、Assessment、學習紀錄和職務能力模型放在一起，並區分「有被提到」和「真的能做到」。

主要資料

職務能力模型、履歷/經歷、專案與工作成果、績效、Assessment、Learning History與Skills Taxonomy

既有系統

HRIS、LMS、Performance Management、Project Systems

03

AI 改變了什麼？

技能資訊大量存在非結構化內容且名稱不一致；AI可將不同技能證據映射到共同Taxonomy並與職務需求比較，但Skill Mention不能直接視為熟練度，仍需要Assessment、工作證據或人工驗證。

04

怎麼解？

先把不同來源的技能證據對應到同一套技能分類，再和職務要求比較，找出有證據支持的能力缺口。熟練度不夠確定的部分，再透過 Assessment、實際工作或主管驗證。

Solution Core

Skill Evidence Mapping + Skill Gap Analysis + Development Recommendation

05

AI 做什麼？

從履歷、專案、工作成果、績效與Assessment抽取技能證據，映射到共同技能分類架構，區分已有證據與仍需驗證的熟練度，辨識並排序職務能力缺口

06

人決定什麼？

HR、L&D與主管定義能力標準，透過Assessment與實際工作證據確認熟練度，並決定培養、實務歷練或其他人才發展措施

07

最後改善什麼？

將人才發展資源集中於有證據支持的能力缺口，提高Skill Gap判斷與發展措施的針對性

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
