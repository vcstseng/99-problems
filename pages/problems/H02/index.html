H02 人資

人才市場這麼大，誰真的值得我們主動去找？

企業僅從主動投遞者中尋找人才時，容易錯過大量符合需求但未主動求職的候選人，而Recruiter難以人工搜尋企業合法可使用的大量歷史人才資料與描述不一致的候選人資訊

01

問題是什麼？

企業僅從主動投遞者中尋找人才時，容易錯過大量符合需求但未主動求職的候選人，而Recruiter難以人工搜尋企業合法可使用的大量歷史人才資料與描述不一致的候選人資訊

02

需要知道什麼？

找被動人才時，不能只靠職稱和關鍵字。要先把職缺真正需要的能力、經驗和產業背景說清楚，再從公司合法可使用的人才庫、履歷與過去互動中找有證據支持的候選人。

主要資料

職缺需求、履歷、技能、工作經歷、產業與候選人互動

既有系統

ATS、HRIS、企業Talent Pool、經授權的Talent Platforms與Resume/Profile DB

03

AI 改變了什麼？

Keyword Search容易漏掉Transferable Skills；LLM/Embeddings可理解履歷與職缺的語意差異，依Skills、Experience與Requirements找到非字面匹配但具有證據的候選人，但需監控訓練資料與Ranking可能帶入的歷史偏誤。

04

怎麼解？

用語意搜尋理解不同寫法背後其實相同的技能與經驗，找出不是字面符合、但能力可轉移的候選人。排序時保留履歷或經歷證據，讓 Recruiter 能快速判斷，而不是直接相信模型分數。

Solution Core

Semantic Talent Search + Candidate-Role Matching + Evidence-Based Ranking

05

AI 做什麼？

理解職缺真正需要的能力與經驗，在企業可合法使用的人才資料中進行語意搜尋，辨識Transferable Skills，建立候選人與職務之間可追溯到履歷與經歷證據的匹配

06

人決定什麼？

定義人才需求、檢查匹配證據與公平性，處理模型無法理解的職涯情境，負責人才接觸及最終聘僱決策

07

最後改善什麼？

擴大有效人才池、提高候選人匹配品質並縮短Sourcing時間，同時降低單靠Keyword與既有職稱造成的漏選

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
