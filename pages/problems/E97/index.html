E97 系統性後果

如果每個 Agent 都把自己的 KPI 做好，為什麼整家公司反而可能變差？

企業部署多個各自追求局部 KPI 的 Agent 後，每個 Agent 都可能在自己的目標與限制內做出合理決策；但當業務、財務、人資、採購、營運等系統同時運作，可能累積出沒有人直接要求、也沒有單一 Agent 負責的整體負面結果。

01

問題是什麼？

企業部署多個各自追求局部 KPI 的 Agent 後，每個 Agent 都可能在自己的目標與限制內做出合理決策；但當業務、財務、人資、採購、營運等系統同時運作，可能累積出沒有人直接要求、也沒有單一 Agent 負責的整體負面結果。

02

需要知道什麼？

每個 Agent 都只看自己的 KPI 時，要一起觀察它們的 Objective、Policy、Action、跨部門依賴與整體 Enterprise Outcome。否則一個部門的改善，可能只是把成本、風險或工作量轉嫁到另一個部門。

主要資料

Agent Objectives、KPIs、Policies、Actions、Cross-Functional Dependencies、Enterprise Outcomes、Constraints

既有系統

Agent Platform、ERP、CRM、HRIS、SCM、EPM、DWH

03

AI 改變了什麼？

多目標最佳化與系統模型本來就能處理多個目標；新的困難在於多個自主決策系統分散在不同功能，各自有自己的目標、狀態、政策與行動迴圈，還會持續改變彼此的環境。模擬與系統層級監控可以探索部分交互情境，但無法替企業定義真正該追求的整體取捨。

04

怎麼解？

把多個 Agent 的目標和行動放進同一個系統層級檢視，透過模擬、回放與整體 Outcome Monitoring 找出交互作用。必要時增加 Cross-Agent Constraint，避免局部最佳化破壞公司整體結果。

Solution Core

System-Level Objectives + Cross-Agent Constraint Management + Interaction Simulation + Enterprise Outcome Monitoring

05

AI 做什麼？

追蹤多個 Agent 的目標、行動與跨部門依賴，模擬或回放它們同時運作時的相互影響，辨識局部 KPI 改善是否正在犧牲其他業務結果、形成回饋循環或意外的系統平衡。

06

人決定什麼？

定義企業層級的取捨、不可犧牲的限制與真正的整體目標，處理沒有任何單一部門願意承擔的跨域代價。

07

最後改善什麼？

更早發現「每個 Dashboard 都是綠的，但公司正在變差」的情況，降低局部最佳化造成的整體傷害；管理問題不能靠一個完美 KPI 解決。

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
