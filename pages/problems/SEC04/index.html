SEC04 安全

MCP、Plugin、Skill 裝進來後，怎麼確認現在安全、更新後也安全？

第三方MCP、Plugin、Skill或Agent元件可能要求過度權限、連接不可信目的地，或在版本更新後改變Capability與Behavior，將新的Supply-Chain Risk帶入企業AI環境

01

問題是什麼？

第三方MCP、Plugin、Skill或Agent元件可能要求過度權限、連接不可信目的地，或在版本更新後改變Capability與Behavior，將新的Supply-Chain Risk帶入企業AI環境

02

需要知道什麼？

MCP、Plugin 或 Skill 是否安全，不能只看第一次安裝。要持續知道來源、版本、簽章、權限、網路目的地、依賴套件與每次更新改了什麼，才能確認更新後沒有偷偷擴權或改變行為。

主要資料

Component Inventory、MCP/Plugin/Skill Manifests、Source/Package Metadata、Permissions、Versions、Signatures、Network Destinations與Dependency Data

既有系統

Plugin/MCP Registry、Package Registry、IAM、SIEM

03

AI 改變了什麼？

傳統Software Supply-Chain Controls仍是主要防線，但AI元件還包含自然語言Tool Description、Instructions與Agent可組合使用的Capabilities。語意分析可協助發現可疑描述與權限組合，但不能取代Allowlist、Version Pinning、Signature、Change Approval與Least Privilege。

04

怎麼解？

先建立公司允許使用的 AI Component Inventory，驗證來源、版本與簽章，並固定已核准版本。更新時自動比較權限、網路存取與能力差異，再把可疑的 Tool Description 或行為交給人工審查。

Solution Core

AI Component Inventory + Provenance/Signature Verification + Version Pinning + Permission Review + Semantic Risk Inspection

05

AI 做什麼？

建立允許使用的AI Component Inventory，驗證來源、版本與簽章，固定核准版本並比較更新前後的Permissions、Network Access與Capabilities；語意分析輔助標示可疑Tool Description或Behavior供人工審查

06

人決定什麼？

核准可信供應商與Components、允許的Capabilities與Permissions，決定版本更新與部署政策；重大Capability或Permission變更必須重新核准

07

最後改善什麼？

降低第三方AI元件、惡意更新與過度權限成為企業攻擊入口的風險，並使元件變更具有可追溯的Approval與Provenance

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
