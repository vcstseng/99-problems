SEC07 安全

AI 出事時，我們看得出它做過什麼、停得下來、還原得回來嗎？

如果企業沒有為 AI 建立足夠的監控與復原設計，安全事件發生後，可能無法重建 Agent 讀過哪些資料、呼叫哪些工具、修改哪些記憶、執行哪些外部操作，也很難及時隔離與復原。

01

問題是什麼？

如果企業沒有為 AI 建立足夠的監控與復原設計，安全事件發生後，可能無法重建 Agent 讀過哪些資料、呼叫哪些工具、修改哪些記憶、執行哪些外部操作，也很難及時隔離與復原。

02

需要知道什麼？

AI 出事後能不能處理，取決於平常有沒有留下足夠紀錄。要能串起 Prompt、檢索來源、模型／Prompt／Policy 版本、Tool Call、外部 Action、Memory Write、身份與網路紀錄，才能重建事情經過。

主要資料

Prompts/Inputs、Retrieved Sources、Responses、Agent State、Tool Calls/Results、External Actions、Model/Prompt/Policy Version、Identity、Memory Writes與Network Logs

既有系統

SIEM、SOAR、Agent Platform、LLM Gateway

03

AI 改變了什麼？

傳統Security Logs通常只能看到API、帳號與Network活動，無法完整重建Agent可觀測的Execution Chain；模型內部Reasoning本身不可作為可靠Audit Record，因此應記錄可觀測的Inputs、Retrievals、Tool Calls、Actions與State Changes。Telemetry本身可能含敏感資料，也需要Access、Masking與Retention Controls。

04

怎麼解？

先建立完整的 AI Security Observability 和執行紀錄。事件發生時可以撤權、隔離 Agent、停止後續操作、還原可版本化狀態；無法直接 Rollback 的外部操作，則啟動事先設計好的補償措施。

Solution Core

AI Security Observability + Execution Trace + Containment + Compensating Actions + Recovery

05

AI 做什麼？

記錄並關聯 Agent 的輸入、檢索來源、Model／Prompt／Policy 版本、工具呼叫、外部操作與記憶寫入，重建可觀測的執行紀錄；事件發生時可撤銷權限、隔離 Agent、停止後續操作、還原可版本化狀態，或執行補償措施。

06

人決定什麼？

判斷事件嚴重度與影響範圍，啟動隔離、法律／合規通報與復原；事先定義哪些操作可以還原、哪些只能補償，以及安全紀錄的存取與保留政策。

07

最後改善什麼？

縮短 AI 安全事件的偵測、調查、隔離與復原時間，降低影響範圍，並保留足以追查事件與改善控制的可觀測證據。
