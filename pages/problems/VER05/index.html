VER05 可靠性與驗證

如果是另一個 AI 在評分，誰來確認這個裁判可靠？

LLM-as-a-Judge可能受到Position、Verbosity、Model-Family Preference等偏誤影響，並與被評估模型共享相同盲點與Failure Modes，使多個AI評分看似一致卻不代表存在獨立Evidence

01

問題是什麼？

LLM-as-a-Judge可能受到Position、Verbosity、Model-Family Preference等偏誤影響，並與被評估模型共享相同盲點與Failure Modes，使多個AI評分看似一致卻不代表存在獨立Evidence

02

需要知道什麼？

如果用另一個 AI 當裁判，就要像管理任何測量工具一樣驗證它。需要 Human Label、Gold Set、Rubric、Deterministic Test、不同 Judge 的分數與版本，才能知道它到底準不準、偏在哪裡。

主要資料

Model Outputs、Judge Scores、Rubrics、Human Labels、Gold Sets、Deterministic Test Results、Disagreement Cases與Judge Version

既有系統

Evaluation Platform、Annotation Tools、CI/Evaluation Store

03

AI 改變了什麼？

AI Evaluator可以大量評估非結構化Output，但Probabilistic Judge不能被直接當成Ground Truth；可靠使用需要以Human-Labeled Gold Set、Deterministic Tests、Bias Tests與Inter-Rater Agreement持續校準，並監控Judge Model更新後的Drift。

04

怎麼解？

用代表性的人工標註案例和確定性測試校準 Evaluator，分析不同 Judge 的一致與分歧，再測試位置、篇幅與 Model Family 造成的偏差。Judge 版本改了，就重新校準，不把它當成永遠正確的標準。

Solution Core

Evaluator Calibration + Gold-Set Validation + Bias Testing + Independent Checks

05

AI 做什麼？

以代表性的Human-Labeled Cases與Deterministic Tests測量Evaluator Accuracy與Bias，分析不同Judges之間的Agreement與Disagreement，測試Position、Verbosity與Model-Family Effects，並在Judge版本變更後重新校準

06

人決定什麼？

建立Gold Standard與Evaluation Rubric，裁決高爭議案例，決定Evaluator可接受誤差與哪些高風險結果不能只靠AI Judge放行

07

最後改善什麼？

避免「AI替AI打分」或多個共享盲點的Judges形成虛假品質保證，使Automated Evaluation本身也受到可量測與可驗證的品質控制

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
