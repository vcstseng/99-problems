VER03 可靠性與驗證

AI 做了很多步驟，中間哪一步出錯？錯誤已經影響到哪裡？

Multi-Step Agent Workflow若缺乏中間狀態驗證與Dependency Trace，一個早期錯誤可能被後續Steps、Agents或Systems當成可信輸入，逐步傳播並形成高影響的Cascading Failure

01

問題是什麼？

Multi-Step Agent Workflow若缺乏中間狀態驗證與Dependency Trace，一個早期錯誤可能被後續Steps、Agents或Systems當成可信輸入，逐步傳播並形成高影響的Cascading Failure

02

需要知道什麼？

多步驟 Agent 出錯時，只看最終結果很難知道錯在哪裡。需要保存每一步 State、Intermediate Output、Tool Result、State Transition 和後續 Action，還要知道哪些下游決策依賴了這一步。

主要資料

Agent Steps、Intermediate Outputs、State Transitions、Tool Results、Business Invariants、Dependency/Execution Graph、Downstream Actions與Business Impact

既有系統

Agent Platform、Workflow Engine、Logs、Event Store、CMDB

03

AI 改變了什麼？

AI Workflow包含Probabilistic Steps，只驗證Final Output難以找出錯誤起點與Downstream Blast Radius；能以Schema、Totals、Referential Integrity、Allowed Values與Business Invariants驗證的Transition應優先使用Deterministic Checks，語意驗證器與Human Review只處理無法形式化的部分。

04

怎麼解？

在高風險的 State Transition 設置 Checkpoint，用確定性 Invariant、獨立 Verifier 或人工檢查中間結果。一旦發現錯誤，就沿 Execution／Dependency Graph 追出已受影響的下游決策、Agent 和交易。

Solution Core

Intermediate-State Verification + Deterministic Invariants + Execution Dependency Graph + Error Propagation Analysis

05

AI 做什麼？

在高風險State Transition設置Checkpoints，以Deterministic Invariants驗證可形式化的State與Tool Results，對語意結果再使用獨立Verifier或人工檢查；一旦發現錯誤，沿Execution/Dependency Graph追蹤已受到影響的Downstream Decisions、Agents與Transactions

06

人決定什麼？

定義Critical Checkpoints、Business Invariants、Stop Conditions與Recovery Priority，判斷受影響結果是否需要撤回、重算、補償或人工處理

07

最後改善什麼？

更早攔截Multi-Step Workflow錯誤，快速定位Failure Origin與Downstream Blast Radius，降低小錯誤累積成Cascading Failure的風險
