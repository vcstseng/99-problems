MG05 管理

當初為什麼這樣決定？後來發生了什麼？我們真正學到了什麼？

重大決策的Assumptions、Alternatives、Expected Outcomes與當時Evidence常散落在簡報、會議與文件裡；幾個月後實際結果出現時，組織難以把Outcome連回原始Decision，容易產生Hindsight Bias，也無法系統化辨識反覆出錯的Assumptions與Decision Patterns。

01

問題是什麼？

重大決策的Assumptions、Alternatives、Expected Outcomes與當時Evidence常散落在簡報、會議與文件裡；幾個月後實際結果出現時，組織難以把Outcome連回原始Decision，容易產生Hindsight Bias，也無法系統化辨識反覆出錯的Assumptions與Decision Patterns。

02

需要知道什麼？

要從決策中學習，必須保留當時的選項、假設、預期結果、信心水準與 Owner，而不是只留下最後結論。之後再把實際 KPI、事件與後續行動連回原決策，才能避免事後重新改寫故事。

主要資料

Decision Memos、Meeting Decisions、Assumptions、Alternatives、Expected Outcomes、Confidence/Ranges、Actual KPIs/Outcomes、Postmortems與Subsequent Actions

既有系統

DMS/Wiki、Collaboration、PPM、EPM/BI、Decision Logs

03

AI 改變了什麼？

AI/LLM可從分散的非結構化Decision Records抽取並標準化「當時相信什麼、預期什麼、選了什麼」，再與後續Actual Outcomes與新Evidence建立Lineage，找出反覆出現的Assumption Error或Decision Pattern；但Outcome Attribution與真正因果仍需要管理者及必要的Causal Analysis判斷。

04

怎麼解？

建立 Decision Memory，在決策發生時記錄理由與假設，之後自動連結實際結果做 Expected-vs-Actual Review。再搜尋歷史上相似決策與反覆失效的假設，讓下一次決策能真正用到過去的經驗。

Solution Core

Decision Memory + Assumption/Outcome Lineage + Expected-vs-Actual Review + Learning Retrieval

05

AI 做什麼？

在決策發生時結構化記錄Decision、Alternatives、Assumptions、Expected Outcome、Range與Owner；之後自動連結實際KPI、事件與Outcome，產生Expected-vs-Actual Review並搜尋歷史上相似決策與重複失效的Assumptions，保留原始Evidence避免事後改寫。

06

人決定什麼？

Management定義什麼算Success/Failure、判斷Outcome與原決策的因果關係，記錄真正的Learning並決定是否修改Strategy、Policy、Decision Rule或未來Assumptions。

07

最後改善什麼？

把一次次重大決策累積成可查證的Institutional Learning，降低Hindsight Bias與重複犯錯，讓未來決策能使用過去真正的Expected-vs-Actual Evidence。

這個問題如何透過 Agent Framework 處理？

先釐清決策與證據需求，再組合顧問 Skills 與允許的 Tools，透過人機協作、安全邊界與治理審查形成方案。框架提供共用方法，不代表本題所有能力都已實作或成果已驗證。
