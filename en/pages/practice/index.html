Problem-Solving Practice

From a problem catalog to evidence-backed, reviewable consulting proposals

We are building a Consulting Agent Group with reusable capabilities for different business problems. A few bounded cases establish the workflow from problem definition to analysis, proposals and management review. Supporting all 99 problems is the goal, not an achieved result.

Updated 2026-10-25 · Synthetic data / simulated management review · An evolving practice record

The consulting agent framework

One reusable operating framework, composed around each problem. Domain expertise and methods can evolve without rebuilding the entire consulting workflow.

Agents · Skills · Tools

Agents coordinate responsibilities; skills provide domain and consulting methods; tools perform bounded data access, calculation and independent checks. Use AI where it adds value, and deterministic methods where they suffice.

Security · Governance

Approved sources, least-necessary access, traceable versions, review gates and stop conditions. People retain accountability and authority; a recommendation is not permission to implement.

Define → investigate → verify → propose → review → hand off. Human supervision spans the whole workflow. The goal is credible consulting deliverables, not autonomous deployment.

All 99 problems have candidate capability mappings; implemented and validated capabilities remain case-specific. F03 provides a complete conditional proposal; CS07 and GOV08 currently demonstrate bounded local workflows. Production security and real-world business outcomes remain unvalidated.

01

Start small; build a reusable method

The Problem Map describes the problems. Methodology explains how they were organized. This page records how we are trying to address them and what has actually been validated.

Define the decision, evidence requirements and success criteria before selecting a method. Use deterministic calculations, rules or process changes where appropriate. AI is not mandatory; model judgments still need evidence, limits and verification.

02

How agents, skills and tools work together

Agents: responsibilities

Planning, domain analysis, verification and management review are logical responsibilities. Each role does not automatically require an independent model; compose the team around the case.

Skills and tools: method and execution

Skills provide methods such as cost variance, hypothesis testing and option comparison. Tools query approved data, calculate and check. A role description or skill document is not proof of implemented capability.

All 99 problems have capability mappings, but only part of the capability catalog is implemented. Current rehearsals largely use fixed rules and synthetic data, not 99 autonomous agents or validated universal problem solving.

03

From problem definition to consulting handoff

  1. Define: establish goals, scope, available data and success criteria.
  2. Plan: select methods, approved tools, responsibilities and evidence needs.
  3. Analyze and verify: run calculations or lookups, then independently check domain arithmetic, sources, versions and authorization.
  4. Compare options: separate facts, causal hypotheses and assumptions; explain trade-offs and recommendations.
  5. Review: request evidence or changes, reverify, accept a bounded deliverable, reject or stop.
  6. Hand off: provide a roadmap, owners, resources, risks, acceptance criteria and unresolved decisions.

The scope is consulting delivery. AI or system needs can become requirements and adoption recommendations; customer software development, deployment and operational changes are outside the current scope.

04

How people supervise agent work

Useful collaboration means being able to inspect, question, return and stop work. Preserve each analysis version with evidence and checks. Bind decisions to the reviewed version; changes require revalidation rather than carrying old acceptance onto new work.

Agents prepare

Analysis, options, assumptions, gaps and documents. They do not grant themselves verification approval or permission to implement recommendations.

People decide

Goals, definitions, professional suitability, resources, acceptable risks and whether to proceed. Real accountable owners retain budget and implementation authority.

Current management instructions and acceptance records are simulated by the same assistant. They are neither the user’s approval nor independent expert review. Human collaboration and usability remain to be tested.

05

Security and governance throughout the workflow

  • Bounded access: host-approved sources and tools; analysis text cannot grant new permissions.
  • Traceable evidence: source hashes, calculations, checks and limitations; changed sources require another review.
  • Versions and recovery: the local case engine persists revisions, instructions and rejected operations, resumes work and blocks stale decisions or conflicting writes.
  • Limited acceptance: accepting analysis does not approve spending, execute changes or eliminate risk. Request evidence or stop when necessary.
  • Clear boundaries: local tests and simulated identities are not production login, enterprise IAM, tenant isolation or security certification.

This website presents static deliverables. It does not expose live case controls or connect to the local agent backend.
