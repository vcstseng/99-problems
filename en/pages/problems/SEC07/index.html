SEC07Security

When AI goes wrong, can we see what it did, stop it, and recover?

Without execution visibility, an AI incident may be hard to reconstruct, contain, or reverse after actions have already affected external systems.

01

What's the problem?

Without execution visibility, an AI incident may be hard to reconstruct, contain, or reverse after actions have already affected external systems.

02

What do we need to know?

Capture prompts, retrieved sources, model and policy versions, state, tool calls, results, external actions, memory writes, identity, and network events.

Key inputs

Prompts/inputs, retrieved sources, responses, agent state, tool calls/results, external actions, model/prompt/policy versions, identity, memory writes, network logs

Existing systems

SIEM, SOAR, agent platform, LLM gateway

03

What does AI change?

AI security requires observable execution and recoverable actions, not just model logs. Some actions can be rolled back; others need compensating action or human recovery.

04

How do we solve it?

Build end-to-end execution traces, emergency containment, rollback where possible, and predefined compensating actions where rollback is impossible.

Solution Core

AI Security Observability + Execution Trace + Containment + Compensating Actions + Recovery

05

What does AI do?

Expose its execution state and action history in a form that security and operations can reconstruct.

06

What do people decide?

Define incident authority, rollback priorities, degraded modes, and recovery ownership.

07

What improves?

Make AI incidents diagnosable and containable instead of opaque and irreversible.
