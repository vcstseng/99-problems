SEC01Security

Can someone hide instructions in a document, email, or web page and take control of the AI?

AI systems can consume untrusted content that contains hidden instructions, creating a path for prompt injection to alter behavior or trigger unsafe actions.

01

What's the problem?

AI systems can consume untrusted content that contains hidden instructions, creating a path for prompt injection to alter behavior or trigger unsafe actions.

02

What do we need to know?

Trace where prompts, email, documents, web content, and retrieved context come from, and distinguish trusted instructions from untrusted data before the model sees them.

Key inputs

User prompts, email, documents, web content, RAG context, content provenance, agent traces, tool calls

Existing systems

LLM gateway, RAG, email, browser, DMS

03

What does AI change?

The model itself cannot reliably decide which text is an instruction and which is merely data. Security therefore depends on isolation, least privilege, provenance, and runtime enforcement around the model.

04

How do we solve it?

Separate trusted instructions from untrusted content, detect suspicious prompt patterns, constrain tool access, and enforce policies outside the model before actions can execute.

Solution Core

Trusted/Untrusted Context Isolation + Prompt Injection Detection + Least Privilege + Runtime Policy Enforcement

05

What does AI do?

Interpret content within a controlled context and surface suspicious instruction patterns without being trusted as the final security boundary.

06

What do people decide?

Define trust boundaries, sensitive actions, and incident response rules.

07

What improves?

Reduce the chance that malicious content can redirect an AI system into unsafe behavior.
