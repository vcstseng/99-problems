SEC03Security

Once AI has tool access, can it be tricked into doing something it is allowed to do—but should not do now?

A valid permission does not mean every action is appropriate in every context, yet agents may execute high-impact actions based on manipulated or incomplete instructions.

01

What's the problem?

A valid permission does not mean every action is appropriate in every context, yet agents may execute high-impact actions based on manipulated or incomplete instructions.

02

What do we need to know?

Connect tool permissions, action parameters, identity, amount, destination, transaction history, approvals, and the business context in which an action is requested.

Key inputs

Tool permissions, API schemas, action parameters, identity, amount/destination, agent traces, transaction logs, approval history

Existing systems

IAM, policy engine, ERP, CRM, payment, email, cloud APIs

03

What does AI change?

AI can propose actions, but authorization should depend on deterministic policy that evaluates context, risk, and authority independently of the model.

04

How do we solve it?

Apply context-aware authorization, least privilege, and mandatory approval rules to every sensitive tool call before execution.

Solution Core

Context-Aware Authorization + Deterministic Policy Enforcement + Least Privilege + Human Approval

05

What does AI do?

Prepare the intended action and context for authorization, but never self-approve outside its authority.

06

What do people decide?

Define decision rights, approval thresholds, and exceptions for high-impact actions.

07

What improves?

Prevent agents from converting legitimate permissions into inappropriate real-world actions.

How does the agent framework approach this problem?

Start with the decision and evidence needs, then combine consulting skills and approved tools under human review, security and governance. The framework defines the approach; this page alone does not establish implemented capability or proven results for this problem.
