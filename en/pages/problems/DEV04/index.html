DEV04AI-Native Development

If the same AI writes the code and the tests, does all-green actually mean correct?

Implementation and tests can share the same mistaken assumption, so passing tests may only prove consistency with the same misunderstanding.

01

What's the problem?

Implementation and tests can share the same mistaken assumption, so passing tests may only prove consistency with the same misunderstanding.

02

What do we need to know?

Use independent requirements, human-defined invariants, contracts, historical bugs, reference behavior, hidden tests, and mutation results.

Key inputs

Code, tests, requirements, human-defined invariants, contracts, historical bugs, reference behavior, hidden tests, mutation results

Existing systems

Git, CI/CD, test framework, mutation-testing tools

03

What does AI change?

Different models do not automatically create independent evidence. Stronger validation comes from different information sources and tests the implementation generator does not control.

04

How do we solve it?

Build property and contract tests from independent requirements, keep held-out cases, and use mutation testing to verify that the tests can actually detect injected faults.

Solution Core

Independent Test Evidence + Mutation Testing + Property/Contract Testing + Deterministic Quality Gates

05

What does AI do?

Generate broad tests from independent evidence and analyze gaps in test coverage.

06

What do people decide?

Define authoritative invariants and maintain independent quality gates.

07

What improves?

Reduce false confidence from code and tests that are wrong in the same way.
