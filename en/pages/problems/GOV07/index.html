GOV07Governance

Six months later, can we reconstruct what AI saw, which rules it used, and what it did?

AI decisions become unauditable when inputs, retrieved evidence, versions, approvals, actions, and memory changes are recorded separately or not at all.

01

What's the problem?

AI decisions become unauditable when inputs, retrieved evidence, versions, approvals, actions, and memory changes are recorded separately or not at all.

02

What do we need to know?

Preserve inputs, model and prompt versions, policy version, retrieved evidence, tool calls and results, approvals, actions, memory writes, and outputs in one lineage.

Key inputs

Inputs, prompt/model/policy versions, retrieved evidence, tool calls/results, actions, approvals, memory writes, outputs

Existing systems

Audit log, agent platform, LLM gateway, DWH, SIEM

03

What does AI change?

AI execution is too dynamic for a simple final-response log. Auditability requires an observable record of the full decision and action path.

04

How do we solve it?

Create a decision provenance trail that links the evidence, versions, approvals, and actions needed to replay or explain a past event.

Solution Core

AI Decision Provenance + Observable Execution Record + Evidence/Version Lineage + Audit Trail

05

What does AI do?

Emit structured execution records and preserve the lineage of evidence used in each decision.

06

What do people decide?

Define retention, audit requirements, and which events require deeper evidence.

07

What improves?

Make AI decisions reconstructable enough for audit, investigation, and accountability.
